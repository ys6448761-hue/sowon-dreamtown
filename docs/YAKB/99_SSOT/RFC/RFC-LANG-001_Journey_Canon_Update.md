# RFC-LANG-001: Journey Canon Update

---

**목적:** `SSOT-JOURNEY-001_Project_Phoenix_Journey_Constitution.md` 작성 과정에서 발견된 RFC 후보(9-2절) 중 확정 가능한 항목을 `SSOT-LANG-001`에 반영한다.
**상태:** **전 항목 승인** — 항목 1·2는 2026-07-04(1차) 승인·반영 완료, 항목 3(재회 vs 재방문)은 2026-07-04(2차, TASK-RFC-002)에 권고안이 승인되어 반영 완료
**제안일:** 2026-07-04
**절차 근거:** `SSOT-LANG-001` 10절 Change Policy(RFC 작성 필수) / `SSOT-OS-001` 변경 절차와 동일
**원본 근거:** `SSOT-JOURNEY-001` 9-2절 RFC 후보 #1(여정/Journey), #4(세 이레·재방문)
**범위 제한:** 이 RFC는 Experience Constitution, Memory Constitution 영역을 다루지 않는다(두 문서 모두 아직 작성되지 않았으며, 이 RFC로 그 내용을 대신 정의하지 않는다)

---

## 1. 배경

`SSOT-JOURNEY-001`을 작성하며 수행한 Language Validation(9절)에서 4건의 RFC 후보가 발견되었다. 본 RFC는 그중 **확정 가능한 2건(여정/Journey 병행 정책, 세 이레 등록)을 처리하고, 나머지 1건(재회 vs 재방문)은 비교 분석 후 권고안만 남긴다.** ("1년" Time Layer 추가와 "나눔" 이중 용법 명문화는 이번 RFC의 범위가 아니며, 별도 RFC 대상으로 남아 있다.)

---

## 2. 항목 1 — Journey / 여정 병행 정책

### 제안 내용

- **Journey** — 공식 브랜드 용어(영문). 시스템명, 제품명, 국제 커뮤니케이션에서 사용.
- **여정** — 공식 한국어 설명 용어. 국문 문서·화면 카피·서술형 설명에서 사용.
- 두 용어는 **동의어의 단순 번역 관계가 아니라, 각자의 문맥에서 공식으로 병행 사용되는 관계**로 확정한다. 어느 한쪽이 다른 쪽의 오기(誤記)나 Alias가 아니다.

### 근거

`SSOT-OS-001` 4절과 `SSOT-JOURNEY-001` 2절이 같은 구조상 위치(DreamTown 다음 단계)에 각각 "Journey"와 "여정"을 써서 표기가 갈린 것이 발견 계기였다. 조사 결과 이는 실수라기보다, **국문 흐름도에는 "여정"이, 브랜드/시스템 명칭 언급에는 "Journey"가 자연스럽게 쓰여온 실제 사용 패턴**과 일치한다. 따라서 하나를 폐기하기보다 "병행 정책"으로 공식화하는 쪽이 실제 용례에 더 부합한다.

### 결정: **승인**

`SSOT-LANG-001` 3절 Canon Language에 반영 완료(4절 참조).

### 영향 문서

| 문서 | 현재 표기 | 조치 |
|------|-----------|------|
| `SSOT-OS-001` 4절 Journey Layer | "Journey" | 유지 — 병행 정책상 허용된 표기이므로 수정 불필요 |
| `SSOT-JOURNEY-001` 2절 Journey 구조 | "여정" | 유지 — 마찬가지로 허용된 표기 |
| `SSOT-LANG-001` 3절 | 기존 "Journey" 단독 정의 | **갱신** — "여정" 신규 등재 + 병행 정책 문구 추가 |

## 3. 항목 2 — 세 이레(21일) Canon Language 신규 등록

### 제안 내용

`SSOT-LANG-001` 3절 Canon Language에 아래를 신규 등록한다.

| 용어 | 정의 |
|------|------|
| 세 이레(21일) | Journey가 일상의 리듬으로 자리 잡는 첫 번째 동행의 시간 |

### 근거

`SSOT-OS-001`(4절)과 `SSOT-JOURNEY-001`(2·5절) 양쪽에서 이미 핵심 구조어로 반복 사용되고 있음에도 `SSOT-LANG-001` Canon Language 표에는 등재되어 있지 않았다. 정의 문구는 `SSOT-JOURNEY-001` 5절 원문("세 이레는 Journey가 일상의 리듬으로 자리 잡는 첫 번째 동행의 시간이다")을 그대로 채택한다 — 새로 정의하지 않고 이미 확정된 문장을 그대로 승격한다.

### 결정: **승인**

`SSOT-LANG-001` 3절 Canon Language에 반영 완료(4절 참조).

### 영향 문서

| 문서 | 현재 상태 | 조치 |
|------|-----------|------|
| `SSOT-OS-001` 4절 | 이미 사용 중, 정의 없음 | 변경 불필요 — 이제 `SSOT-LANG-001`이 정의를 제공 |
| `SSOT-JOURNEY-001` 2·5절 | 이미 사용 중, 정의 있음(원본) | 변경 불필요 — 원본 정의가 Canon으로 승격됨 |
| `SSOT-LANG-001` 3절 | 미등재 | **갱신** — 신규 행 추가 |

## 4. 항목 3 — 재회 vs 재방문 비교 분석 및 권고안

### 4-1. 두 용어 비교

| 항목 | 재방문 | 재회 |
|------|--------|------|
| 문자적 의미 | 다시 방문함(행위) | 다시 만남(관계) |
| 현재 사용처 | `SSOT-OS-001`(Journey Layer, Time Layer, Service Layer), `SSOT-JOURNEY-001`(2·6절) | `SSOT-JOURNEY-001` 6절에서 이번에 처음 제안됨(등재된 곳 없음) |
| 코드/운영 레벨 사용 | **실사용 중** — `daily-miracles-mvp/scripts/retention-cron.js`(Day1/3/7 이탈 방지 리텐션 넛지), `check-day3-inactive.yml` 등에서 "재방문 유도"라는 뜻으로 이미 쓰이고 있음(`Aurora_Aurum_Audit.md` §5) | 없음 |
| 함의 | 객관적·행동적(앱을 다시 연다) — 마케팅/리텐션 지표에 적합 | 정서적·관계적(과거의 자신과 다시 만난다) — `SSOT-JOURNEY-001` 6절이 그리는 "의식(ritual)"에 더 적합 |
| 충돌 위험 | **있음** — "재방문"을 철학적 의식의 이름으로 쓰면, 이미 운영 중인 리텐션 지표 용어("재방문율" 등)와 같은 단어를 다른 두 의미로 쓰게 되어 `Project_Phoenix_Language_Audit.md`가 지적한 "체크인" 4중 충돌과 같은 패턴이 재발할 소지가 있음 | 낮음 — 아직 다른 용도로 쓰인 적 없는 단어라 충돌 위험이 없음 |

### 4-2. 프로젝트 내 기존 유사 판례

이 프로젝트는 이미 **같은 개념을 서로 다른 청중(내부 운영 vs 사용자 경험)에 맞춰 다른 단어로 분리하는 방식**을 여러 번 채택해왔다:

- `dreamtown-wishart` CON-004: "항로명과 여행 상품명은 다른 체계다. 혼용하지 않는다" — 감정 분류용 내부 용어와 고객향 상품명을 의도적으로 분리
- `SSOT-LANG-001` 8절: "나눔"(리액션)과 "공명"(공감)을 폐기하지 않고 **공존 확정**
- `SSOT-JOURNEY-001` 9-1절: "나눔"이 리액션 용법과 철학적 원칙 용법으로 **이중으로 쓰이고 있음을 이미 확인**

### 4-3. 권고안

**"재방문"을 폐기하고 "재회"로 전면 교체하는 것은 권고하지 않는다.** 대신 위 판례와 동일한 패턴으로 **역할을 분리하는 것을 권고한다**:

- **재방문** — 운영/분석 레벨 용어로 유지. 코드·크론잡·리텐션 지표 등 기존 시스템은 그대로 둔다(Alias Policy 적용 대상, 수정 불필요).
- **재회** — `SSOT-JOURNEY-001` 6절이 그리는 "과거의 자신과 현재의 자신이 다시 만나는 의식"을 가리키는 **경험/카피 레벨 공식 용어**로 신규 채택할 것을 권고한다.

이 권고안은 최초 작성 시점(2026-07-04, 1차)에는 확정이 아니었다. **2026-07-04(2차, TASK-RFC-002)에 사용자 승인을 받아 아래와 같이 확정한다.**

### 결정: **승인** (2026-07-04, TASK-RFC-002)

- 재방문 = 운영/리텐션/분석 용어로 유지
- 재회 = Journey 경험/의식/사용자 메시지 용어로 신규 채택
- `SSOT-LANG-001` Canon Language에 "재회" 등재 완료, 3-1절에 역할 구분표 반영 완료(4-1의 구분과 동일 내용)

### 영향 문서 — 실제 반영 여부

| 문서 | 현재 표기 | 조치 |
|------|-----------|------|
| `SSOT-LANG-001` 3절·3-1절 | 미등재 | **반영 완료** — "재회" Canon 등재 + 역할 구분표 추가 |
| `SSOT-JOURNEY-001` 2절 Journey 구조 | "재방문" | **미반영** — TASK-RFC-002 범위 밖(수정 대상에 포함되지 않음). 필요 시 별도 RFC-JOURNEY로 진행 |
| `SSOT-JOURNEY-001` 6절 "재방문 원칙" | "재방문" | **미반영** — 위와 동일 사유 |
| `SSOT-OS-001` 4·8·9절 | "재방문" | **미반영 — 의도적** — TASK-RFC-002가 "SSOT-OS-001 수정 금지"를 명시했으므로 승인된 내용이라도 이번에는 반영하지 않는다 |
| `daily-miracles-mvp` 코드/크론 | "재방문"(리텐션 로직) | 변경 없음(Alias Policy, TASK-RFC-002도 코드/DB 수정 금지 명시) |
