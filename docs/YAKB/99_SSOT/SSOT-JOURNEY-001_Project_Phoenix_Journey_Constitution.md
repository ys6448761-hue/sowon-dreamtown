# SSOT-JOURNEY-001: Project Phoenix Journey Constitution

---

**목적:** Project Phoenix에서 Journey가 무엇인지 최상위 원칙으로 정의한다. 이 문서는 Journey OS, Product, AI Companion, DreamTown, Memory, Community의 기준 문서가 된다.
**최상위 Authority:** `docs/YAKB/00_ARCHITECTURE/Architecture_Constitution.md` (SSA — Foundation. 본 문서와 충돌하면 Architecture Constitution이 우선한다)
**Level:** Domain Constitution (Journey) — `SSOT-OS-001` 2절 "Constitution Layer"가 "작성 예정"으로 표시했던 자리를 채우는 문서
**Status:** Approved
**버전:** 1.0
**확정일:** 2026-07-03
**변경 절차:** 임의 변경 금지. 변경 시 `RFC-JOURNEY-{번호}_{제목}.md` 작성 (`SSOT-LANG-001` 10절과 동일 절차)
**참조 문서:** `SSOT-LANG-001_Project_Phoenix_Language_Constitution.md`, `SSOT-OS-001_Project_Phoenix_Operating_System.md`, `Architecture_Constitution.md`

> This Constitution is governed by CORE-PRINCIPLES-001.

---

## 1. Journey는 여행이 아니다

Journey는 여행이 아니다.

Journey는 사람이 일상 속에서 자신을 발견하고, 소원을 만나고, 실천하고, 기억하고, 다시 성장하는 삶의 순환이다.

---

## 2. Journey 구조

```
일상
  ↓
문제
  ↓
소원
  ↓
DreamTown
  ↓
여정
  ↓
기억 봉인
  ↓
세 이레(21일)
  ↓
동행
  ↓
재방문
  ↓
나눔
  ↓
새로운 Journey
```

> **Language Validation 메모(9절 상세)**: `SSOT-OS-001` 4절 "Journey Layer"의 동일 흐름도는 이 자리(DreamTown 다음, 기억 봉인 이전)에 **"Journey"**(영문)를 썼는데, 본 문서는 **"여정"**(국문)을 쓴다. 같은 자리를 가리키는 두 표기가 오늘 작성된 두 문서 사이에서 이미 갈렸다 — 9절에서 RFC 후보로 기록한다.
>
> **✅ 처리 현황(2026-07-04, TASK-GROWTH-001)**: 이 11마디 구조는 `SSOT-GROWTH-001_Growth_Architecture.md` 5-1절에서 공식 9단계 Growth Architecture로 압축 대응되었다(원문 미변경 — Growth Architecture는 이 구조의 압축형으로 정의됨).

## 3. DreamTown은 Journey의 끝이 아니라 시작이다

DreamTown은 Journey의 끝이 아니라 시작이다.

---

## 4. 별씨앗 Journey

| 별 | 정의 |
|----|------|
| 반투명 별 | 가능성을 품은 별 |
| 황금 별 | 약속을 기억하는 별 |
| 야광 별 | 동행의 별 |
| 별의 기억 | Journey를 봉인한 기억 |
| 별자리 | 연결된 삶 |

> **Language Validation 메모**: `SSOT-LANG-001` 5절 "Product Language"(반투명=가능성을 품은 별 / 황금=약속을 기억하는 별 / 야광=동행의 별 / 별의 기억=Journey 봉인 / 별자리=연결된 삶)와 대조한 결과, **다섯 항목 모두 의미가 일치**한다. "별의 기억" 항목만 canon의 "Journey 봉인"을 "Journey를 봉인한 기억"으로 풀어 쓴 차이가 있으나 뜻이 갈리지 않아 새 정의로 취급하지 않는다.

---

## 5. 세 이레(21일)

세 이레는 Journey가 일상의 리듬으로 자리 잡는 첫 번째 동행의 시간이다.

야광별은 세 이레 동안 별빛 대화/오늘의 별을 이어간 소원이에게 보내는 동행의 증표다.

> `SSOT-LANG-001` 7절이 "별빛 대화/오늘의 별"의 적용 범위를 "소원 관련 감정 체크인"으로 한정한 것과 이 문장이 정확히 일치한다 — 별개 시스템(출석 포인트, Plaza 온도, QR 현장 체크인)까지 확장하는 서술이 아님을 확인했다.

---

## 6. 재방문 원칙

재방문은 관광 재방문이 아니다.

과거의 자신과 현재의 자신이 다시 만나는 의식이다.

DreamTown은 인생의 기준점이다.

---

## 7. 나눔 원칙

Journey의 완성은 소원 성취가 아니라 나눔이다.

소원이는 소망이가 되어 다른 예비 소원이의 Journey를 돕는다.

> **Language Validation 메모**: 이 절의 "나눔"은 `SSOT-LANG-001` 8절이 정의한 "나눔(참여형 리액션: 기적나눔·지혜나눔·감사나눔)"과 다른 층위의 용법이다 — 여기서는 리액션 버튼이 아니라 **Journey 전체를 완성시키는 철학적 원칙**을 가리킨다. `Architecture_Constitution.md` 제3장 성장 모델("나눔 → 새로운 소원")의 "나눔"과는 같은 층위·같은 의미로 일치한다. 상세는 9절 참조.

---

## 8. Time Layer

Project Phoenix는 공간뿐 아니라 시간을 설계한다.

3개월, 6개월, 1년 후 기억을 다시 열어 성장의 변화를 확인한다.

> **Language Validation 메모**: `SSOT-OS-001` 9절 "Time Layer"는 "3개월 → 6개월 → 재방문 → 새로운 자신"까지만 정의했다. 이 문서가 추가한 **"1년"** 지점은 `SSOT-OS-001`에 아직 없는 새 마디다 — 9절에서 RFC 후보로 기록한다.

---

## 9. Language Validation

`SSOT-LANG-001_Project_Phoenix_Language_Constitution.md`의 Canon Language(3절)·Product Language(5절)·금지 용어(8절)를 기준으로, 본 문서에서 사용한 용어를 전수 대조했다. **신규 용어는 캐논에 자동 반영하지 않고, 아래 RFC 후보 표로만 기록한다.**

### 9-1. 기존 캐논과 일치 확인된 용어

| 용어 | 사용처 | 대조 결과 |
|------|--------|-----------|
| Journey | 전체 | 일치 |
| DreamTown | 3절 | 일치 |
| 소원이 / 소망이 / 예비 소원이 | 7절 | 일치(예비 소원이는 `SSOT-LANG-001`에서 이미 신규 선언된 용어) |
| 반투명 별 / 황금 별 / 야광 별 / 별의 기억 / 별자리 | 4절 | 일치(4절 메모 참조) |
| 동행 | 2·5·6절 | 일치 — Long-Term Companion과 동일 개념으로 사용됨 |
| 별빛 대화 / 오늘의 별 | 5절 | 일치, 범위(소원 관련 체크인 한정)도 일치 |
| 나눔 | 7절 | **부분 일치** — 8절의 리액션 정의와 다른, 더 넓은 철학적 층위로 사용됨(`Architecture_Constitution.md` 제3장과는 일치). 두 용법이 공존한다는 점을 `SSOT-LANG-001`에 명시할 필요 있음 |

### 9-2. RFC 후보 (신규/미확정 용어 — 자동 추가하지 않음)

| # | 용어/표현 | 발견 위치 | 문제 | RFC 후보 내용 | 처리 현황 |
|---|-----------|-----------|------|----------------|-----------|
| 1 | 여정 (Journey 구조 5번째 단계) | 본 문서 2절 | `SSOT-OS-001` 4절은 같은 자리에 "Journey"(영문)를 쓰는데 본 문서는 "여정"(국문)을 씀 — 같은 자리를 가리키는 표기가 문서마다 다름 | `RFC-LANG-{n}`: Journey 구조 5번째 단계의 공식 표기를 "Journey"와 "여정" 중 하나로 확정하고, "여정"이 "Journey" 전체와 어떻게 다른지(하위 단계 vs 동의어) 정의 필요 | ✅ **처리 완료** — `RFC-LANG-001_Journey_Canon_Update.md`, 병행 정책으로 확정(둘 다 유지), `SSOT-LANG-001` 3절 반영 |
| 2 | 1년 (Time Layer 세 번째 회고 시점) | 본 문서 8절 | `SSOT-OS-001` 9절 Time Layer에는 "3개월→6개월"까지만 있고 "1년"이 없음 | `RFC-OS-{n}`: `SSOT-OS-001` 9절에 "1년" 마디를 추가할지 결정 | ⏳ 미처리 — 이번 RFC-LANG-001 범위 밖 |
| 3 | 나눔의 이중 용법(리액션 vs 철학적 원칙) | 본 문서 7절 | `SSOT-LANG-001` 8절은 나눔을 리액션 3종으로만 정의 — 본 문서의 "Journey 완성 = 나눔" 용법은 별도로 정의된 적 없음(단, `Architecture_Constitution.md`와는 일치) | `RFC-LANG-{n}`: `SSOT-LANG-001` 3절 Canon Language에 "나눔"을 "① 리액션 체계 ② Journey 완성 원칙"의 이중 정의로 명문화 | ⏳ 미처리 — 이번 RFC-LANG-001 범위 밖 |
| 4 | 세 이레(21일) / 재방문 | 본 문서 2·5·6절 | `SSOT-OS-001` 4절 Journey Layer에는 있으나 `SSOT-LANG-001` 3절 Canon Language 표에는 아직 없음 — Journey 흐름의 핵심 개념인데 언어 헌법에는 등재되지 않은 상태 | `RFC-LANG-{n}`: "세 이레(21일)"와 "재방문"을 `SSOT-LANG-001` 3절 Canon Language에 정식 등재 | ⚠ **부분 처리** — "세 이레(21일)"는 `RFC-LANG-001`로 등재 완료. "재방문"은 "재회"로의 대체 여부를 비교 분석했으나 **확정 보류**(권고안만 존재, `RFC-LANG-001` 4절 참조) |

### 9-3. SSOT-OS-001 갱신 필요 사항 (참고 — 직접 수정하지 않음)

`SSOT-OS-001`은 "Constitution Layer"(2절)에서 Journey Constitution을 "작성 예정"으로 표시하고 있으나, 본 문서 작성으로 그 상태가 바뀌었다. 다만 `SSOT-OS-001`도 RFC 절차 없이는 임의 변경하지 않는 문서이므로, **이 사실을 여기에 기록만 하고 `SSOT-OS-001` 본문은 직접 수정하지 않는다.** 반영은 `RFC-OS-{n}`을 통해 진행할 것을 권고한다.
