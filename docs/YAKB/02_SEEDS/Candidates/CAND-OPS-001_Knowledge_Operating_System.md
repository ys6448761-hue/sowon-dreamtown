## Purpose

이 저장소의 정체성 자체를 규정하는 선언이다: 저장소를 "문서를 모아두는 곳"이
아니라 "지식이 생성·검토·성장·고정되는 운영체계"로 정의함으로써, 앞으로 만들어질
모든 Candidate/SSOT/RFC 문서가 왜 그 거버넌스 절차(GOV-001)를 거쳐야 하는지에
대한 근거를 명문화한다.

## Background

2026-07-14 세션에서, Claude Code가 Level 4 감지 → Candidate 생성 → GOV-001
lifecycle → YAKB 등록으로 이어지는 파이프라인을 실제로 수행하는 것을 지켜본
대표님이, 그 동작 패턴 자체가 이 저장소의 성격을 규정한다고 판단하여 제안했다.
CLAUDE.md 말미에 선언문으로 추가해달라는 요청과 함께 등장했다.

## Core Definition

Project Phoenix 저장소는 문서 저장소(Document Repository)가 아니라, 지식이
생성·검토·성장·고정되는 Knowledge Operating System이다.

## Principles

1. 저장소는 문서를 쌓아두는 아카이브가 아니라, 지식이 상태(State)를 가지고
   움직이는 시스템이다 (`GOV-001` Idea → Draft → Review → Approved → LOCKED).
2. 모든 아이디어는 등장한 즉시 영구 자산이 되지 않는다 — 반드시 거버넌스를
   통과해야 한다.
3. Claude Code는 이 운영체계의 실행자(Knowledge Architect)이며, 문서를
   대신 써주는 도구가 아니다.
4. 이 원칙 자체도 다른 SSOT와 동일한 절차(Review → Approved)를 거쳐야
   승격되며, 예외를 두지 않는다.

## Applications

- `CLAUDE.md` 전체의 존재 이유를 설명하는 최상위 선언
- 신규 참여자/AI 온보딩 시 가장 먼저 전달할 프레이밍
- 향후 `Architecture_Constitution.md` 또는 `GOV-001`과의 관계 정리 시 참조점

## Example

- 좋은 예: "이 아이디어는 아직 Idea 단계이니 Candidate로 만들어 Review를
  거치자."
- 나쁜 예: "일단 대화에서 나온 좋은 말이니 그냥 README에 바로 박아넣자."
  (거버넌스를 건너뛰는 방식은 이 원칙과 충돌한다)
